# MVP：任职资格认证主链

Status: ready-for-agent
来源：PRD《AI+HR 智能体系统（以任职资格与绩效管理为中心）》+ ADR-0001~0011

## 一句话定义

在虚拟租户中，用状态机驱动一条完整认证链：**建标 → 绩效导入 → 认证（举证/考试/评审）→ 画像 → 差距分析 → IDP**，全程留痕，AI 内容带「AI 生成·待审核」标记。

## 验收标准（ADR-0011）

虚拟租户内选定 1 个序列、10–50 名虚拟员工，走完：建标 → 员工举证 → AI 出题考试 → 按认证路由评审 → 落库生效 → 生成画像 → 差距分析 → 派生 IDP。

## 范围内 / 范围外

| 范围内（MVP） | 范围外（后置） |
|---|---|
| 组织/岗位/职级通道主数据 | 人才盘点批次、九宫格、人才结构图 |
| 任职资格标准库（1 个序列） | 继任者计划、梯队池、AB 角 |
| 绩效结果导入（CSV + 手工补录） | 绩效考核流程本身 |
| 认证状态机 + 认证路由 | 复评降级（P4/P5 三年复评） |
| AI 出题（知识四档→题型映射） | 调薪引擎、工资管理 |
| 画像引擎最小版（七维快照） | 模板市场、配置 UI、套餐计费 |
| 差距分析（五类）+ 动作路由 + IDP | AI 材料预审（B 类，stretch） |
| 微信小程序员工端 | 钉钉 H5（除非首个真实客户用钉钉） |
| tenant_config 壳 + ai_usage 流水 | RBAC 全矩阵（MVP 只做 4 角色） |

## 技术栈（ADR-0007）

- 后端 NestJS + MySQL 8.0，RESTful `/api/hr` 前缀，JWT 鉴权
- 管理端 React；员工端微信小程序
- LLM 直连国内模型 API（豆包/通义），不引入编排框架
- 新代码库（ADR-0002），本仓库仅存 spec 与工单

## 架构原则

- Workflow 管骨架：认证链路由状态机驱动，非法迁移由引擎拦截
- 人工确认闸门：认证结论、IDP 生效一律「草稿 → 确认 → 生效」
- AI 边界：A 类（出题）产出必审；一切 AI 调用写 `ai_usage`
- 多租户：所有核心表带 `tenant_id`，逻辑隔离；配置经 `tenant_config` 读取，默认值即 PRD 写死值（ADR-0006）

## MVP 数据模型（表清单）

主数据：`tenant`（最小注册表）、`org_department`、`org_position`、`org_employee`（员工主数据）、`qc_channel`
标准库：`qc_standard`、`qc_standard_duty`、`qc_standard_knowledge`、`qc_standard_ability`
业务链：`perf_result`、`cert_record`、`exam_question`、`profile_snapshot`、`gap_analysis`、`idp`
平台：`tenant_config`、`ai_usage`

DDL 以 PRD「数据表 DDL 设计」章为准；每表追加 `tenant_id` 分区键；`org_employee` PRD 未给 DDL，按最小字段（id/姓名/部门/岗位/职级/入职日期）自建。

## 认证状态机（MVP 子集）

主链：发起 → 硬校验 → 材料预审 → 考试 → 答辩/评审 → 生效（回写画像）
异常分支（PRD 异常表全量实现，补偿参数走 tenant_config）：

| 异常 | 流转 | 参数 |
|---|---|---|
| 硬校验不通过 | → 已终止（未达标） | 业绩条件（B 级/A 级门槛） |
| 材料驳回 | 预审 → 补充，可多次重提 | 重提次数 |
| 考试不通过 | → 补考 → 通过/终止 | 补考次数（默认 1） |
| 答辩不通过 | → 已终止（带改进意见） | 冷却期 |
| 超时未完成 | → 自动关闭 | 时限（按批次） |
| 员工撤回 | → 已撤回（评审开始后不可撤） | — |

认证路由（ADR-0006 可配）：P1→P2 部门经理单审；P2→P3 认证小组（3–5 人）表决；P3 以上管委会终审。MVP 角色简化：员工/HR/部门经理/高管，认证小组与管委会由 HR 指派人员承担。

## 画像引擎最小版（ADR-0005）

输入：导入的 `perf_result` + 生效的 `cert_record` → 生成 `profile_snapshot`（七维 JSON：基本条件/业绩/团队贡献/职责履行/知识技能/能力素质/绩效），版本化，可追溯。首批画像由绩效导入触发；认证生效时回写。MVP 不做测评问卷，「潜力」维度留空。

## 差距分析与 IDP

- 差距分析：`qc_standard` × 画像现状比对，五类 gap_type（业绩/履职/能力/团队贡献/知识）
- 动作路由（确定性规则）：业绩→绩效改进、履职→过程监督、能力→行为改善、团队贡献→团队任务、知识→学习
- IDP：员工季度周期；AI 可依差距生成 IDP 草稿（A 类，待审核），人工确认生效

## API 清单（MVP 子集）

统一响应壳 `{ code, message, data }`；列表默认分页 + 关键字筛选。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/hr/perf/import | 绩效结果 CSV 导入 |
| POST | /api/hr/exam/generate | AI 生成试卷（→ 待审核） |
| POST | /api/hr/exam/submit | 提交考试 |
| POST | /api/hr/cert/apply | 认证申请（触发硬校验） |
| POST | /api/hr/cert/review | 评审表决（按路由） |
| GET | /api/hr/profile/{employee_id} | 画像快照查询 |
| POST | /api/hr/match/analyze | 差距分析 |
| POST | /api/hr/idp | 创建 IDP（AI 草稿或人工） |
| GET | /api/hr/idp | IDP 查询 |
| GET | /api/hr/channel | 职级通道查询（员工端） |

## 页面清单

管理端（React）：标准库维护、绩效导入、试卷审核、认证管理/评审、画像查询、差距看板、IDP 管理、用量报表
员工端（小程序）：职业生涯通道、认证举证上传、在线考试、我的 IDP

## 安全合规（MVP 要点）

- 敏感数据：绩效与画像按角色掩码；MVP 无薪酬数据
- AI 脱敏：出题不涉人员数据；IDP 草稿调用前脱敏（去姓名/工号）
- 所有写操作留审计日志；AI 请求/响应留痕

## 里程碑

1. M1 数据就绪：虚拟租户主数据 + 种子标准库入库（issues 01–02）
2. M2 认证链通：状态机 + AI 出题 + 考试评审跑通（issues 03–04）
3. M3 闭环达成：画像 → 差距 → IDP，验收场景走通（issues 05–07）
