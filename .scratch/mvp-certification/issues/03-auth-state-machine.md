# 03 认证状态机与路由

Status: done
Blocked by: 01, 02

## 任务

实现 MVP 核心链路：认证申请 → 硬校验 → 材料预审 → 考试闸口 → 按路由评审 → 生效回写，状态机驱动，异常分支全量。

## 范围

1. 状态机实现（spec.md「认证状态机（MVP 子集）」）：主链 6 态 + 6 类异常分支，非法迁移统一拦截，全量审计日志
2. 硬校验规则：基本条件 + 业绩条件（B 级/A 级门槛），规则参数从 tenant_config 读取
3. 认证路由：P1→P2 部门经理单审；P2→P3 小组（3–5 人）表决；P3+ 管委会终审。MVP 角色简化为 员工/HR/部门经理/高管，小组与管委会由 HR 指派
4. 接口：`POST /api/hr/cert/apply`（含 auto_check 返回）、`POST /api/hr/cert/review`
5. 管理端页面：认证列表/详情、评审操作台；留痕展示

## 验收

- 正例：P2→P3 员工走完 申请→校验→预审→考试通过→小组表决→生效，cert_record 落库且触发画像回写
- 反例：业绩不达标 → 已终止（未达标），不产生评审记录；考试不过 → 补考 1 次 → 终止并关联知识差距
- 撤回/超时/驳回重提分支各有至少 1 个测试用例
- 所有迁移有审计日志（操作人/时间/原因/前后状态）
