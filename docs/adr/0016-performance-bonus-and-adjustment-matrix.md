# 绩效奖金与调薪矩阵：人才激励体系（P2）设计

_Status: accepted, 2026-10-04。细化并部分修订 ADR-0015 路线图中的 P2 表述；不追溯修改 ADR-0015 正文。_

## 背景

用户提供的《绩效管理》材料明确了三件原系统缺失的事：(1) 绩效结果 SABC 五档带**分数带与绩效系数**（S 1.5 / A 1.2 / B 1.0 / C 得分÷80 / D 0.5）与强制分布区间；(2) 绩效工具分工——KPI/PBC 挂钩奖金等直接利益，OKR 不挂钩，360 只用于晋升/干部选拔/培训；(3) 结果四出口（薪酬福利、职务调整、PIP、培训发展），D 等级对应 PIP、降职降薪或解除合同。

系统现状只有固定月薪与薪级带宽，原型调薪引擎直接消费原始分数，没有浮动薪酬、奖金包、固浮比与 PIP 实体；CONTEXT 已立原则"以岗定级、以级定标、以能定薪、以绩定奖"，其中"以绩定奖"没有落点。本轮只做文档与设计，不写功能代码；实现节奏沿用 ADR-0015：P1 先做绩效内生（周期 SABC 结果的生产者），P2 再建激励（本 ADR 的消费者）。

## 决策

### 1. 薪酬结构：固定工资 + 唯一浮动实体「绩效奖金」

- 员工年现金收入 = **固定工资**（走等级工资表：带宽、薪档、市场分位）+ **绩效奖金**（按考核周期计发，可季可年）。
- 全产品只有一个浮动薪酬实体，统一命名**绩效奖金 (Performance Bonus)**；不再分设"绩效工资""年终奖"两套机制（项目未上线，不背双轨包袱）。
- **目标奖金**不进员工档案。方案测算时按 **序列固浮比（目标月数）× 当期固定月薪**实时计算，允许在方案内对个人覆盖目标月数，覆盖必须留痕。调薪生效后下一周期奖金基数自动跟随，无冗余数据。
- 固浮比（pay mix）按序列/岗位族配置（如销售高浮动、研发职能低浮动），随配置中心走，与材料中 KPI/OKR 的岗位分野对齐。

### 2. 绩效奖金计算公式与消费边界

- **实发绩效奖金 = 目标奖金 × 个人绩效系数 × 组织绩效系数**。
  - 个人绩效系数取该考核周期的 SABC 结果：S=1.5、A=1.2、B=1.0、C=得分/80、D=0.5。
  - 组织绩效系数本期**预留位、缺省 1.0**；组织评价方式（完成率映射或部门 SABC）在 P1 绩效模块以配置项决定，本 ADR 不锁死。
- 奖金计算**只消费 KPI/PBC 等考核型工具产生的周期 SABC 结果**：只用 OKR 的团队不计发；周期内无有效等级的员工（新手期——考核从"有经验"阶段开始、新入职、期内入离职）不计发、不推测系数（与"绝不造分"原则一致）。
- **360 评估结果明文禁止进入薪酬计算**，只用于晋升、干部选拔与培训设计。
- 周期内薪酬/在职状态变动按**时间加权折算**：目标基数取自调薪历史分段加权，期内入职按在职月数折算；折算默认开启、可按租户关闭；方案明细展示折算系数与在职月数。

### 3. 奖金包（池）约束

- 方案录入**奖金包总额**，默认按各部门"目标奖金基数合计"占比预切**部门包**；包内**等比缩放为默认行为**，缩放以部门包为单位，部门包可手工微调（必填理由、留痕）。
- 方案明细展示"公式应发 / 包内实发 / 缩放比"。
- 奖金包与年度调薪预算是两个不同的包：**奖金包 = 周期浮动薪酬总额；调薪预算 = 年度固定成本增量**，文档与界面不得混用。

### 4. 年度调薪：SABC × 带宽渗透率矩阵，全员覆盖

- 废弃原型"核心岗位 × 原始分数 ≥85 入池、90/95 分给 6/8/10%"的规则，替换为**调薪矩阵**：
  - 行 = 周期绩效等级 S/A/B/C/D；列 = **带宽渗透率**四档（<0.40 / 0.40–0.70 / 0.70–0.90 / ≥0.90，渗透率 =（现薪−带宽下限）/（上限−下限））。
  - 单元格 = 建议涨薪 %，整表为平台默认值、租户可在配置中心覆盖；负向单元格只对 D 且 PIP 不通过者生效，不做自动降薪。
  - 结果导向：S/A 给涨薪，B 视预算给零或小涨，C 冻结，D 转 PIP。
- 覆盖面**放开为全员**；原 PRD"年底调薪只给核心岗位上的核心人才"降级为**预算不足时的排序策略**（低薪高能、核心岗位优先），不再是资格门槛。
- **75 市场分位停涨保留**，作为矩阵计算之后的硬覆写：命中即建议 0% 并标注外部竞争性原因。

### 5. 定薪与定奖不串道；PIP 是唯一接口

- **以能定薪**（岗位价值/职级带宽/认证晋升 → 岗变薪变，走晋升联动调薪）与**以绩定奖**（周期 SABC → 绩效奖金）是两条不相交通道。
- 绩效等级**不直接改固定月薪、不做按系数即时改薪**；绩效对固定工资的影响只通过年度调薪矩阵发生。
- D 等级出口：进入 **PIP（绩效改进计划，归 P1 绩效模块，在改进计划上扩展周期与结论）**。PIP 通过 → 维持；不通过 → 系统自动生成降职/降薪联动调薪建议单，进入调薪审批人工闸门（降幅由矩阵 D 行或规则给出）。解除劳动合同不做线上流程，仅做档案状态标记与提醒。

### 6. SABC 常量与强制分布：平台默认、租户覆盖、软校验

- 默认分数带与系数：**S ≥95 分（1.5，0–5%）、A 90–95（1.2，0–15%）、B 80–90（1.0，15–80%）、C 65–80（得分/80，与 D 合计 0–10%）、D <65（0.5）**。材料原文 S 行"9 分以上"按"95 分以上"解释（与 A 的 90–95 衔接）。
- 分数线、系数、分布比例三组常量全部作为平台默认值，租户可在配置中心覆盖并留痕；C 的线性公式形态固定（得分÷常数），常数可配。
- 强制分布为**软校验**：按**考核批次**（可圈定部门/序列范围）统计实际占比并与区间比对，超界允许覆盖但必填理由、全程留痕。理由：比例是弹性区间且小团队天然无法满足分布，硬阻断不可行。配置中心原"271/361"措辞同步替换为 SABC 区间。

### 7. 奖金方案状态机与发放落点

- 状态机：**草稿 → 已测算（含缩放后清单）→ 审批中 → 已批准 → 已归档**。驳回回草稿、包超限阻断（沿用调薪审批的异常分支模式）。
- 系统不发钱、不对接财务、不做工资条。批准后产出只读**奖金发放清单**（可导出给财务）并落发放结果（每人目标额/个人与组织系数/应发/部门包缩放比/实发），供审计、本人查询与跨年度对比。

### 8. 权限与可见性（P2 实现时登记权限点目录）

- 新增权限点 **`bonus.manage`**（奖金方案/测算/清单）与 **`comp.rule.manage`**（调薪矩阵、固浮比、SABC 系数与分数线配置），授予 hr_coe_comp 与 tenant_admin；`comp.band.manage` 仍只管带宽与市场数据。
- exec 审批时**汇总金额可见（总包/部门包/总额对比）、个人金额掩码**。
- manager/hrbp **不参与奖金分配**（不做主管提名分钱）；方案批准后仅可见本团队成员的等级与系数，不可见金额。
- 员工本人在"我的薪酬"可见本人已批准的奖金结果；SSC 全员薪酬掩码，仅在授权的发放清单导出场景执行、不浏览明文。

### 9. 建设边界

- **P2 只做三块**：等级工资（带宽/薪档/市场分位）、周期调薪（矩阵 + 75 分位停涨 + PIP 联动）、绩效奖金（系数 + 奖金包 + 折算 + 发放清单）。
- 津贴补贴与福利、短中长期/股权、荣誉表彰保持 P3 远期，不在本 ADR 范围。

## 后果

- PRD 模块二重写为「绩效评价与改进」（四循环、工具分工、SABC 与软校验、PIP）、模块八重写为「薪酬激励」（本 ADR 全部规则）；配置中心、接口清单、DDL、流程图同步更新。
- P1 绩效内生必须产出可供消费的周期 SABC 结果（等级、分数、考核工具类型、考核批次范围、组织系数预留位），否则 P2 奖金无数据源。

- 术语进 CONTEXT.md：绩效奖金、目标奖金、固浮比、绩效系数、调薪矩阵、带宽渗透率、奖金包、PIP、SABC 强制分布。
